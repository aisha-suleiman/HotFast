# Shawarma Bot

Telegram-бот доставки шаурмы для Сирии: интерфейс на арабском и русском, оплата через
ShamCash (подтверждение вручную) или наличными, доставка по геолокации либо самовывоз.
Кухня работает из закрытой Telegram-группы — отдельной админки нет.

---

## Что умеет

**Клиент.** Выбирает язык → собирает заказ из меню с опциями (размер, соус, добавки) →
корзина → доставка по геолокации или самовывоз из филиала → телефон (необязателен) →
способ оплаты → подтверждение. Получает уведомление на своём языке при каждой смене статуса, видит историю
заказов и может повторить любой из них одной кнопкой.

**Кухня.** Заказ приходит в группу одним сообщением: состав, суммы, адрес, телефон,
кликабельный контакт клиента. Для доставки следом приходит сообщение-локация — курьер
открывает её в картах одним тапом. Кнопки под карточкой ведут заказ по статусам; каждое
нажатие редактирует то же сообщение и добавляет строку в журнал внизу.

**Две цены.** Цены заданы в одной валюте (турецкие лиры), а рядом показывается сумма в
долларах по живому курсу с [sp-today.com](https://sp-today.com/en): `150 ₺ ≈ 3.10 $`.

**ShamCash.** Бот показывает кошелёк и точную сумму, принимает скриншот перевода и номер
транзакции, пересылает чек в группу. Кухня жмёт «Принять» или «Оплата не пришла». Если за
`PAYMENT_TIMEOUT_MIN` минут оплата не подтверждена — заказ отменяется сам (в Docker —
проверка каждую минуту, на Vercel — раз в сутки, см. ниже).

## Быстрый старт на Windows

Скопируйте `.env.example` в `.env` и впишите `BOT_TOKEN`. Дальше достаточно запустить
`run.bat` — двойным кликом или из терминала:

```powershell
.\run.bat
```

Он сам создаст виртуальное окружение, поставит зависимости, применит миграции и запустит
бота. Меню заливается отдельно, один раз и после каждой правки `seed/menu.yaml`:

```powershell
.\.venv\Scripts\python.exe -m scripts.seed_menu
```

### Если хочется вручную

Обратите внимание: в Windows PowerShell **нет оператора `&&`** — команды выполняются по
одной, каждая своей строкой.

```powershell
py -m venv .venv
```

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

```powershell
.\.venv\Scripts\python.exe -m bot
```

На Linux и macOS вместо `.\.venv\Scripts\python.exe` используйте `.venv/bin/python`,
а команды можно объединять через `&&`.

### Как узнать ADMIN_GROUP_ID и ADMIN_IDS

Создайте закрытую группу, добавьте туда бота, дайте право отправлять сообщения и напишите
в группе `/chatid` — бот ответит идентификатором. Он отрицательный, вида `-1001234567890`.

Та же команда в личке с ботом вернёт ваш собственный Telegram ID — его вписывают в
`ADMIN_IDS`.

### Если бот не запускается

| Сообщение в логе | Что делать |
|---|---|
| `Telegram отклонил BOT_TOKEN` | скопировать токен заново: @BotFather → `/mybots` → API Token |
| `Бот не видит группу кухни` | добавить бота в группу и разрешить отправку сообщений |
| `CERTIFICATE_VERIFY_FAILED` | переустановить зависимости: в них есть `truststore`, который отдаёт проверку сертификатов системе |
| `REDIS_URL не задан` | предупреждение, не ошибка: в разработке допустимо, в проде — нет |
| `Это обычная группа, а не супергруппа` | взять `ADMIN_GROUP_ID` заново: Telegram сменит id группы при первой смене её настроек |
| `Лексема "&&" не является допустимым разделителем` | это PowerShell: выполняйте команды по одной, `&&` в нём не работает |
| `Telegram не ответил (попытка N из 5)` | не ошибка: первое соединение через VPN часто не успевает установиться, бот повторит сам |
| `Связаться с Telegram пока не удалось` | бот запустился и продолжает попытки в фоне; перезапускать не нужно |

Проверка сертификатов через `truststore` включается сама на старте. Она нужна, потому что
Python на Windows не умеет догружать промежуточные сертификаты, а система умеет; то же
касается антивирусов, подменяющих сертификаты. Это не отключение TLS — проверка остаётся
полной, меняется только источник доверенных корней.

## Боевой запуск

```bash
docker compose up -d --build
```

Compose поднимает PostgreSQL, Redis и бота; миграции применяются при старте контейнера.
Меню заливается один раз:

```bash
docker compose exec bot python -m scripts.seed_menu
```

`REDIS_URL` в проде обязателен: без него состояние оформления заказа теряется при
перезапуске, и клиент, дошедший до выбора оплаты, окажется в пустоте.

## Деплой на Vercel

На Vercel нет постоянного процесса, поэтому там бот работает иначе, чем в Docker: вместо
long polling — **вебхук** (`bot/web.py`), вместо фоновых циклов — **cron раз в сутки**
(`vercel.json`; время в UTC, Дамаск = UTC+3):

| Задача | Когда (Дамаск) | cron (UTC) |
|---|---|---|
| `/cron/expire` — отмена неоплаченных заказов ShamCash | в полночь | `0 21 * * *` |
| `/cron/rates` — обновление курса | в 9 утра | `0 6 * * *` |

На бесплатном тарифе Vercel запускает cron в любую минуту указанного часа, а не ровно в
00:00 и 09:00. Заказ отменяется, если ему больше `PAYMENT_TIMEOUT_MIN` минут, поэтому
созданный за полчаса до полуночи доживёт до следующей.

**1. Внешние сервисы.** SQLite и память на Vercel не сохраняются, нужны:
[Neon](https://neon.tech) (Postgres) и [Upstash](https://upstash.com) (Redis).
Строка Neon должна быть вида
`postgresql+asyncpg://USER:PASS@HOST/DB?ssl=require` (именно `ssl=`, не `sslmode=`).
Redis — `rediss://default:PASS@HOST:6379`.

**2. Миграции и меню** — один раз, с вашего компьютера, с `DB_URL` от Neon в `.env`:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

```powershell
.\.venv\Scripts\python.exe -m scripts.seed_menu
```

**3. Проект на Vercel.** Импортируйте репозиторий на vercel.com, в *Settings → Environment
Variables* перенесите всё из `.env` (кроме путей к SQLite) и добавьте `WEBHOOK_SECRET` и
`CRON_SECRET` — любые длинные случайные строки. `REDIS_URL` обязателен.

**4. Зарегистрируйте вебхук** — после первого деплоя, подставив свой адрес:

```powershell
.\.venv\Scripts\python.exe -m scripts.set_webhook https://ВАШ-ПРОЕКТ.vercel.app
```

Скрипт выведет адрес вебхука и последнюю ошибку Telegram, если она была.

Локальный запуск через `python -m bot` (polling) снимает вебхук: пока вы тестируете у себя,
боевой бот на Vercel молчит. После тестов повторите шаг 4.

## Настройка под заведение

Всё, что меняется без правки кода, лежит в двух файлах.

**`.env`** — токены, часы работы, валюта, реквизиты ShamCash, тарифы доставки:

```env
DELIVERY_TIERS=[{"max_km":15,"fee":6000}]
FREE_DELIVERY_FROM=50000
MIN_ORDER_TOTAL=20000
```

Все суммы — в минорных единицах валюты: `15000` при `CURRENCY=TRY` означает 150 ₺. Дальше
последнего тарифа доставка недоступна: клиент получит вежливый отказ с контактом поддержки.

**`seed/menu.yaml`** — блюда, цены, варианты порций. Сейчас в меню две позиции —
шаурма и донер, у каждой выбор порции «обычная / дубль (больше мяса)». Цены в файле —
**заглушки**, подставьте реальные.

После правки:

```bash
docker compose exec bot python -m scripts.seed_menu
```

Скрипт **синхронизирует** базу с файлом, а не просто дополняет её:

| В файле | Что произойдёт |
|---|---|
| блюдо добавлено | появится в меню |
| цена или название изменены | обновятся |
| блюдо удалено | снимется с продажи (`is_active = false`), но останется в базе |
| вариант порции удалён | исчезнет из карточки товара вместе с кнопкой |

Снятые блюда не удаляются: на них ссылается история заказов, и удаление стёрло бы её.
Вернуть блюдо в продажу — просто добавить его в файл обратно и запустить скрипт.

В конце скрипт печатает, что именно изменилось:

```
Меню синхронизировано с menu.yaml.
  Товаров в меню: 2
  Сняты с продажи: falafel, fries, cola
```

Пока раздел в меню один, экран выбора раздела не показывается — клиент из главного меню
сразу попадает к блюдам. Как только разделов станет больше одного, экран появится сам.

### Конвертер валют

Курс берётся со страницы sp-today.com. Публичного JSON у сайта нет — их API платный и по
заявке, — поэтому читается структурированный payload, который Next.js кладёт прямо в HTML.
Это надёжнее разбора вёрстки: имена полей меняются реже, чем CSS-классы.

Котировки на сайте даны к сирийскому фунту, поэтому курс «лира → доллар» считается
кросс-курсом через фунт: 1 ₺ = 2.73 SYP, 1 $ = 132.00 SYP, значит 1 ₺ ≈ 0.0207 $.

```env
SECONDARY_CURRENCY=USD   # пусто — конвертер и вторая цена выключены целиком
RATE_MODE=sell           # sell / buy / mid
RATE_CITY=damascus       # damascus или alhasakah
RATE_TTL_MIN=60          # как часто обновлять в фоне
RATE_MAX_AGE_HOURS=48    # старше — вторую цену не показываем
```

Что происходит, когда сайт недоступен:

| Ситуация | Поведение |
|---|---|
| Сайт не отвечает | остаётся последний известный курс, в лог идёт предупреждение |
| Бот перезапустили | курс поднимается из базы, вторая цена видна сразу |
| Курс старше `RATE_MAX_AGE_HOURS` | показывается только точная цена в лирах |
| Сайт сменил формат | тест `test_rates.py` падает на фикстуре, цена деградирует до одной |

Курс никогда не запрашивается по ходу отрисовки цен: фоновая задача обновляет его раз в
`RATE_TTL_MIN` минут, хендлеры читают готовое значение из памяти. Медленный чужой сайт не
может задержать ответ клиенту.

**Курс фиксируется в заказе.** При подтверждении в заказ записывается снимок курса, и
история с карточкой кухни считаются по нему. Сумма, которую клиент видел при оформлении, не
меняется задним числом от того, что доллар за ночь подорожал.

Вторая цена идёт после «≈» и намеренно подана как ориентир: точная сумма — всегда в валюте
меню, по ней и принимается оплата.

### Команды владельца

Доступны тем, чей Telegram ID указан в `ADMIN_IDS`:

| Команда | Что делает |
|---|---|
| `/photo <slug>` в ответ на фото | привязывает фотографию к блюду |
| `/stop <slug>` | убирает блюдо из продажи и возвращает обратно |
| `/stats` | число пользователей |
| `/chatid` | id текущего чата |

Фотографию нельзя задать из YAML: у Telegram она существует только как `file_id`, который
выдаётся при загрузке.

## Проверка

```bash
.venv/Scripts/python.exe -m pytest -q
```

Тесты покрывают то, где ошибка дороже всего: подсчёт денег, границы зон доставки, таблицу
переходов статусов (каждый разрешённый проходит, каждый запрещённый бросает исключение),
нормализацию телефонов, полноту обеих локалей и сборку карточки заказа на реальной базе.

### Ручной прогон перед сдачей

На тестовом боте и тестовой группе:

1. `/start` → арабский → меню → блюдо с опциями → корзина → доставка → локация **в зоне** →
   телефон или «Пропустить» → наличные → подтвердить. В группе появилась карточка и сообщение-локация.
   Прогнать все статусы до «Доставлен», сверяя уведомления у клиента.
2. То же с локацией **вне зоны** — заказ не создаётся, показан контакт поддержки.
3. ShamCash: заказ → реквизиты → скриншот → номер транзакции → «Оплата подтверждена».
   Повторить с «Оплата не пришла» и с истечением таймаута.
4. Самовывоз: выбор филиала, «Готов» → «Выдан».
5. Переключить язык на русский и пройти путь заново — непереведённых строк быть не должно.
5a. Вторая цена: сверить `≈ N $` в карточке блюда, корзине и на подтверждении. Затем
   поставить `RATE_URL` на заведомо нерабочий адрес и убедиться, что бот стартует и
   показывает одну цену вместо двух, а не падает.
6. Перезапустить бота посреди оформления: состояние восстанавливается из Redis.
7. Заказ в нерабочие часы — отказ с указанием времени работы.

## Устройство

```
bot/
├── config.py        настройки из .env, валидация на старте
├── i18n.py          загрузчик локалей, ar/ru
├── db/              модели, репозитории, сессия
├── services/        логика без Telegram: деньги, зоны, статусы, уведомления
├── handlers/        сценарии: старт, каталог, корзина, оформление, оплата, кухня
├── keyboards/       клавиатуры и схемы callback-данных
├── middlewares/     сессия БД, пользователь и язык, антифлуд
└── locales/         ar/txt.ftl, ru/txt.ftl — весь текст, видимый пользователю
```

Два места стоит знать, прежде чем что-то менять:

**`bot/services/orders.py`** — словарь `ALLOWED` описывает все переходы статусов. Из него
строятся и кнопки в группе, и валидация. Добавить кнопку в запрещённый статус физически
невозможно, поэтому новый статус добавляется правкой одной таблицы.

**`bot/locales/*/txt.ftl`** — в коде нет ни одной строки, видимой пользователю. Тест
`test_i18n.py` падает, если в одном языке появился ключ, которого нет в другом.

### Отличия от исходного плана

- **i18n без `aiogram-i18n` и Fluent.** Написан свой загрузчик `.ftl` на 90 строк
  (`bot/i18n.py`). Полный Fluent нужен ради плюрализации, а в текстах бота нет ни одной
  фразы, где шесть арабских форм множественного числа что-то решают: количество везде
  показывается цифрой рядом с названием. Формат файлов совместим, так что переход на
  `fluent.runtime` не потребует правок на стороне вызова.
- **Приём чека ShamCash сделан без FSM.** Состояние живёт в самом заказе, поэтому клиент
  может прислать скриншот через час, после перезапуска бота или после отказа кухни.
- **Добавлены три команды владельца** (`/photo`, `/stop`, `/stats`). Без `/photo` поле
  `photo_file_id` было бы недостижимо: `file_id` выдаёт только Telegram при загрузке.
- **Курс снимается со страницы, а не из API.** Публичного эндпоинта у sp-today нет,
  их API платный и выдаётся по заявке. Если заведение его купит, замена сведётся к телу
  метода `RateProvider._fetch` — остальной код о происхождении курса ничего не знает.
- **Добавлена зависимость `tzdata`** — на Windows и в slim-образах Linux нет системной базы
  часовых поясов, и `Asia/Damascus` роняет бота на старте.
